# MIQOS Desktop Configuration Contract v1.0

**Gateway:** G5  
**Status:** FROZEN AT G5

## 1. Authoritative Desktop deployment profile

Each packaged Desktop build contains one immutable non-secret deployment profile generated by the controlled build.

Logical schema:

```json
{
  "schemaVersion": "miqos-desktop-config-v1",
  "profileId": "test-synthetic",
  "deploymentStage": "TEST",
  "applicationEnvironment": "SYNTHETIC",
  "api": {
    "baseUrl": "https://example.invalid",
    "audience": "miqos-api-test"
  },
  "oidc": {
    "issuer": "https://example.invalid",
    "clientId": "public-native-client-id",
    "scopes": ["openid", "profile"]
  },
  "features": {},
  "build": {
    "sourceCommit": "git-sha",
    "buildId": "ci-build-id"
  }
}
```

Values above are illustrative, not real environment configuration.

## 2. Profile authority

The deployment profile is:

- generated/validated during build;
- bundled as a local application resource;
- associated with the package identity;
- treated as non-secret but integrity-sensitive;
- loaded by the Tauri native core;
- validated before protected application startup;
- exposed to the renderer only as a sanitised typed configuration ViewModel.

For signed releases, profile integrity is covered by the signed application/package artefact.

## 3. No production runtime override

In installed TEST/STAGING/PRODUCTION packages:

- process environment variables do not override the bundled profile;
- command-line arguments do not override security endpoints/environment;
- user config files do not override security endpoints/environment;
- registry values do not override security endpoints/environment;
- WebView/local storage does not override security endpoints/environment.

Changing an API/issuer/environment binding requires a new controlled package unless a future cryptographically authenticated remote/managed configuration mechanism is separately designed and approved.

## 4. Development profile generation

DEVELOPMENT may use local developer environment inputs to generate the same typed profile contract at startup/build time.

Local development inputs may come from ignored local files such as `.env.local`, but:

- they are not the production configuration mechanism;
- they must pass the same schema/coherence validation;
- they must not contain secrets destined for renderer bundling;
- the generated DEVELOPMENT profile must remain SYNTHETIC.

The existing repository `.env.example` remains a legacy/source-development aid and is not the Desktop production authority.

## 5. CI/test profile generation

CI supplies deterministic non-secret TEST profile inputs through the workflow/build environment.

The build writes the validated profile into the package resources and records a redacted configuration fingerprint in build evidence.

CI secrets are consumed only by the native/security/build steps that need them and must never be serialised into the profile.

## 6. Required fields

Required deployment profile fields:

- schema version;
- profile ID;
- deployment stage;
- application environment;
- API base URL;
- API audience;
- OIDC issuer;
- OIDC native/public client ID;
- OIDC scopes;
- feature-flag object;
- source commit;
- build/run ID or deterministic local-development marker.

## 7. URL rules

For STAGING/PRODUCTION:

- API and issuer URLs must be HTTPS;
- loopback, localhost and private developer endpoints are rejected;
- URL user-info components are rejected;
- fragments are rejected;
- API base URL must not contain arbitrary path/query data beyond the approved base form.

DEVELOPMENT/TEST may use loopback/local endpoints when explicitly classified SYNTHETIC.

## 8. Secret prohibition

The deployment profile must not contain:

- OAuth client secret;
- access token;
- refresh token;
- signing key;
- database credential;
- provider credential;
- confidential API key.

Vite-exposed environment values are client-visible and therefore are not a secret-storage mechanism.

## 9. Renderer configuration ViewModel

Renderer receives only values required for presentation/routing, for example:

```text
deploymentStage
applicationEnvironment
profileId
buildVersion/buildId
sanitised service identity
feature availability
```

The renderer does not need raw token configuration or secrets.

Native transport/auth code consumes the full validated non-secret profile internally.
